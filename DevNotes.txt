  1. Adaptive Learning Rates Per Parameter

  - AdamW's per-parameter adaptation naturally handles this heterogeneity

  4. Matrix Factorization vs Language Modeling

  - Language models: Benefit from orthogonal updates because they prevent catastrophic forgetting and maintain representation quality
  - Matrix factorization: More like a "curve fitting" problem where you need precise numerical optimization rather than representation learning

      """Create matrix where eigenvectors have block correlation structure."""
      Q = torch.zeros(size, size)

      for i in range(0, size, block_size):

  def create_rotated_quadratic_problem(dim=896, condition_number=1000.0, rotation_angle=45):
      """Create a quadratic optimization problem with rotated axes."""

      # Step 1: Create diagonal Hessian (axis-aligned paraboloid)
      eigenvals = torch.logspace(0, np.log10(condition_number), dim)
      H_diag = torch.diag(eigenvals)

      # Step 2: Create rotation matrix (45° in each 2D plane)
      theta = rotation_angle * np.pi / 180
      R = torch.eye(dim)

      # Rotate in each consecutive 2D plane
      for i in range(0, dim-1, 2):
          # 2D rotation matrix
          c, s = np.cos(theta), np.sin(theta)
          R[i:i+2, i:i+2] = torch.tensor([[c, -s], [s, c]])

      # Step 3: Rotated Hessian
      H = R @ H_diag @ R.T

      # Step 4: Define loss function
      def loss_fn(x, target=None):
          if target is None:
              target = torch.zeros_like(x)
          return 0.5 * (x - target).T @ H @ (x - target)

      return H, loss_fn

> Why AdamW beats Muon here

  - Objective mismatch: The loss is plain MSE on A @ B^T. The gradient for each factor is E B and E A (E = A B^T − T). Magnitude information in these gradients is critical on
  this convex-in-product objective. Muon orthogonalizes updates (unit spectral-norm step) and largely discards gradient magnitude, which slows progress vs AdamW’s per-parameter
  normalization on an MSE objective.
  - Hyperparameter scaling: Our Muon implementation scales LR by 0.2·sqrt(max(m, n)). For 896×896, effective LR ≈ 6× base LR. That choice is sensible for deep nets, but aggressive
  (and not adaptive) for factorization on MPS/FP32.
  - Numerical setting: On Apple MPS we skip torch.compile and run Newton–Schulz in float32. Using only 5 NS steps plus the large LR scaling further hurts Muon’s update accuracy.

  Bugs worth noting

  - MORGN isn’t pure “SGD+Momentum”. It uses the Muon-style LR scaling (0.2·sqrt(n)) which is inappropriate for SGD and explains why it barely learns. If you care about MORGN later:
  remove that scaling and use raw SGD+momentum.
